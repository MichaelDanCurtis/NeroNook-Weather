# Weather Observatory for NeroNook

Independent native macOS module, version 0.4.0. Forecast / Map / Coast share a custom widescreen interface inside the Nook and in the larger independent window. Explore hourly weather, daily details, observed radar/infrared history, selectable Earth and Windy wind/temperature maps and nearby tides. Location, units, source health and full alerts are behind the gear.

**Default location follows this Mac.** Core Location asks for macOS permission; no assumed city's weather is fetched while initial permission/location is unresolved. Coordinates are rounded to three decimal places before weather requests. Location is rechecked every 30 minutes, with immediate manual retry. Place search and presets provide a manual override. Location, timezone and Fahrenheit/Celsius preferences belong to the plugin and persist across updates.

## Independence and provenance

NeroNook 0.26.1 supplies generic custom-view raster resources and isolated loopback and separately negotiated HTTPS documents. Older hosts retain the 16:9 diagram fallback and independent-window action. The vendored SDK is a source snapshot, not a dependency on the host checkout. No weather implementation is added to the host. No other installed desktop app, system Node/Python, externally managed web server, website login, browser session or other plugin is required. Windy is an optional plugin-owned API connection.

The original source was recovered from the owner's Weather Observatory Sites project into `/Volumes/Main External/Development/Weather-Observatory-Source`, commit `7f2416ebab5f2c0647f597c6a2d49d038eed8ea5`. Selected adapters and normalization logic are retained under `Worker/observatory`: weather/NOAA/MET fallback, marine, air, point alerts, place search, radar, satellite history, cyclones and tides. The published website and its access policy were not changed. Native views and the bundled map are new module-specific surfaces. This release does not duplicate every website feature.

A private child process runs the bundled JavaScript adapters through newline-delimited messages. Weather feeds use no listening port. When a Windy key is saved, the same private worker serves three bundled map assets on a random loopback-only port behind a per-process capability path. It is not a general proxy; Host, method and exact asset paths are checked, CORS and caching are disabled, and its endpoint stops with the process. Its Node 22.23.0 executable ships inside `Contents/Helpers`; the Swift plugin owns process shutdown. The native wrapper constrains provider hosts, redirects, timeouts, response size and pending requests. Site/Google credentials and environment variables are never imported. Worker environment is deliberately minimal.

## Choose your maps

Select **Earth · no account** or **Windy · your account** from the Wind/Temperature map toolbar, or Weather settings → Sources. The choice persists across restarts and updates. New and pre-provider settings default to Earth while retaining existing location, units and Windy credentials.

Earth displays the live public `https://earth.nullschool.net/` viewer inside a sandboxed child frame. It is not a data API, a copied service, or a locally maintained globe. Earth deliberately limits embedded controls. The Nook shows wind/temperature previews; **Open Earth viewer** opens a separate plugin-owned, top-level WebKit window with Earth's original menu, zoom, date and unit controls. No scripts are injected into that page, and it receives no host tools. The Observatory unit button is hidden on Earth maps because it cannot control Earth's internal units. The initial view centers on the selected region rounded to 0.1 degrees. Refreshing ordinary forecast data does not reset globe exploration. Layer changes recreate the embedded Earth document because its preview does not follow fragment changes interactively. Leaving Map, changing providers, or closing the window removes that viewer. Closing the full Earth window releases its web view. Availability and behavior depend on the third-party site.

Windy is optional. Each user signs up/signs in at the official API key page, creates a **Map Forecast API** key and saves it in this plugin's secure field. A normal Windy/Premium account alone is not an API entitlement. Setup guidance includes the app identifier and loopback restrictions. No shared developer key is bundled and choosing a provider never registers an account or buys a plan. The saved private testing key remains available when switching back to Windy.

## Data and behavior

- NOAA/NWS forecast first for US points, with Open-Meteo and MET Norway fallbacks. Forecast values are labeled as estimates; validity and model issue times differ from fetch time.
- Temperature, wind and rain probability for the next 24 hours, with pointer/keyboard scrubbing and a seven-day outlook. Daily details show only supplied values; unknown measurements stay missing.
- Open-Meteo Marine waves/swell/period, offshore model-cell distance, and NOAA nearby tide predictions relative to MLLW. Coarse ocean forecasts are distinct from land weather.
- CAMS via Open-Meteo US AQI, NWS point alerts and NOAA NHC/CPHC cyclone inventory. Missing/failed alerts never imply an all-clear.
- Bundled Leaflet with a subdued OpenStreetMap basemap, RainViewer radar/coverage and NOAA infrared history. Play, pause, scrub and return to the latest advertised frame. The time uses the selected location timezone; radar time identifies a composite frame, not every source scan. Layers load independently; missing tiles never imply an all-clear.
- Official Windy Map Forecast API wind particles, point picker and temperature overlays using the GFS development tier. The plain Map layer becomes Temperature. The plugin loads the official remote Windy library in a sandboxed child document with no access to the Nook's event bridge. Wind/temp switches preserve the instance; leaving Map releases it. Selected location and °F/°C preferences transfer to Windy. Ordinary current/hourly forecast values remain explicitly attributed to their existing provider, not relabeled as Windy.
- The Map Forecast API key belongs to this plugin's Keychain item and goes to its worker through a private pipe. It is never in host snapshots, settings JSON, command-line arguments or logs. Only the temporary document capability URL reaches the host. Sources settings provide secure key entry, reconnect and removal. The free testing tier is development-only and capped at 500 sessions/day; no paid plan has been purchased.
- Map imagery passes through `view-resources-v1` as bounded raster bytes. Native URLSession owns fixed-provider requests, HTTP cache, response bounds and cooldown. No map code or provider URLs enter the host. Leaving Map or closing its native window stops the view. No bulk downloading or offline map download feature.
- Adapter request caching, deduplication and provider Retry-After cooldown are reused. Failed refreshes keep previous data with explicit errors; recent cached values can be shown while reconnecting. Public feeds refresh on a five-minute cycle while visible; individual source caches enforce their own longer TTLs.
- Read-only shared SDK `read_status` and a status channel. No weather-triggered device actions or safety/route recommendations.

## Build

Apple Silicon, macOS 14+, full Xcode/Swift 6; development uses Node/npm. Run `npm ci`, `bash scripts/prepare-runtime.sh`, `swift test`, `Runtime/node --experimental-strip-types --test Worker/tests/*.test.mjs`, and `bash scripts/package.sh`. Set `NERONOOK_SIGNING_IDENTITY` to a stable signing identity. The runtime helper downloads a pinned official Node archive and checks its SHA-256. Runtime and generated build artifacts are ignored by Git.

Install `build/Weather Observatory.app` through NeroNook Settings → Modules. Grant Location access for Weather Observatory when prompted. Tests can use `--protocol-test` to suppress location requests. `scripts/check-live.py` checks public feeds for a fixed Honolulu fixture without changing app settings. `scripts/test-protocol.py` verifies SDK presentation and rejection of unsupported actions.

## Release boundaries

Google WeatherNext, Earth Engine and Google basemap credentials need a separately authorized plugin-owned connection. Those layers remain unconnected. Tracking extras, 3D atmosphere, tide-station override, combined animated layers and locally rendered global atmospheric fields are not included in 0.4.0. Windy uses its official development API; production licensing is still required before distributing that integration. Earth is displayed as an unmodified public website; its assets and data have not been copied or proxied. Its publisher directs licensing inquiries to [Nullschool Technologies](https://nullschool.net/); production integration rights have not been established by this local preview. The module is development-signed, not notarized or published. Distribution requires reviewing provider commercial-use terms, quota handling and supported platforms; Open-Meteo's free endpoint is not an implied commercial license. The included Node and Leaflet licenses are shipped with the app. Attribution remains visible.
